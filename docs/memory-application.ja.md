# 記憶の適用と検証

OpenCodeで取得した記憶について、現在の根拠、採否、守る条件、反例、検証方法を記録できます。通常の作業継続は妨げず、未処理・失敗・失効した検証を根拠にした `fresh` 完了を拒否します。

1. `task_prepare` の `memoryApplication` または `task_memory_status` で対象を確認する。
2. `task_memory_review` で `adopt`、`not_applicable`、`contradicted` を記録する。現在の根拠は必須。採用時は `invariant`、`counterexample`、`verificationMethod` も指定する。
3. コード変更では `task_memory_verify` に明示的な実行ファイル・引数・相対cwd・タイムアウトと依存ファイルを渡す。既存の検証実行器がコマンドを実行する。既に実行した検証を申告する場合は `task_memory_evidence` を使う。
4. 返された `evidenceId` を適用記録の `evidenceIds` に設定する。更新時は現在の `expectedRevision` と新しい `requestId` を使う。
5. 新しいエラーや対象ファイルが判明したら `task_context_refresh` に同じrun・能力一覧・現在の `expectedContextRevision` を渡す。準備のやり直しでrunを増やさない。

適用記録と証拠は配信IDと記憶revisionに紐付きます。配信や記憶revisionの変更後には再確認が必要です。PLANやコードレビューでは採否と検証方法を記録し、実装テストは要求しません。特定の過去スキーマのfixtureに固定番号を使う場合は、不適用の理由を記録できます。

`model_reported` はモデルの申告です。`host_executed` はKiokukoが実行して観測した結果です。後者は実行前後のリポジトリ状態も照合します。両者をOpenCodeのクライアントフックが観測した結果として表示することはありません。本文や完全な出力ログは保存せず、終了状態と状態digestを保持します。実行中に切断された要求の再送はコマンドを再実行せず、不明のまま返します。

`doctor` は記録数と観測方式を表示します。runごとの未処理・失効状態は `task_memory_status` で確認します。setupで配布される `memory-reasoning` もこの手順を案内します。既存の設定方式を使うため追加フック設定は不要です。

## 保証範囲

- 記憶取得を省略した編集そのものを禁止する機能ではありません。現在のOpenCode連携は助言方式を維持します。
- モデル申告の証拠は、申告時点からの依存ファイル変更を検出します。実行済みであることや依存ファイルの網羅性は証明しません。
- ホスト実行ではGitが列挙する追跡対象・未追跡ファイルを既存の状態検査で照合します。無視対象の外部環境や実行後も動くすべての外部プロセスまで証明するものではありません。
- `completed` と検証済みは別です。失敗・中断・キャンセルや、検証未完の通常終了を無限の続行要求へ変えません。
- 検索結果の `retrieval` は配信、一次スコープ内の記憶なし、検索不一致、スコープ除外を区別します。過去配信を再利用した空結果は `historical_empty` とし、当時の不明な理由を捏造しません。文字数不足や検索障害は例外として返します。
